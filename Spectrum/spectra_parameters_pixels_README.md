# Spectral samples CSV

`spectra_parameters_pixels.csv` is generated by `../export_spectra_csv.py`. It replaces the array-in-cell layout for use in Excel. The original `spectra_parameters.csv` is left unchanged.

Each row is one wavelength sample. Wavelength, flux, inverse variance, and masks each occupy a separate numeric cell. Metadata and available parameters repeat for each sample. Group by filename or observation_key to recover each spectrum, ordered by zero-based pixel_index. One observed spectrum need not mean one unique star.

Wavelengths are in Angstroms and follow the original FITS wavelength grid. Flux and inverse variance retain their native numerical units. LAMOST flux units are marked unspecified where absent from the header. No normalization, radial-velocity correction, or resampling was performed. Missing parameters and uncertainties are blank; nonfinite sample values are blank rather than zero. Zero inverse variance and quality masks are retained.

SDSS teff_K and logg are existing ELODIE pipeline estimates, with explicit provenance and unvalidated status. They are not validated ground-truth labels. The LAMOST files contain no temperature/gravity values, and neither group supplies their uncertainties.

For Excel, use Data > From Text/CSV and set obsid to Text before loading to preserve long numeric identifiers. The observation_key column prefixes identifiers with their survey (for example SDSS:123...) and therefore also preserves the identifier as text when opened directly. Do not save over the CSV after Excel converts obsid to a number. Numeric CSV values preserve source precision, while Excel may round their display.

All 698,086 samples fit below Excel's worksheet row limit. The summary JSON is generated with counts and generation time. This file is an extraction, not a model-ready SLAM training set.
